Software, without becoming a software engineer.

A real team, with faces

A Product Partner, Planner, Architect, Builder, Tester, Reviewer, Security engineer, Scribe and Release engineer. Talk to them, watch what each one is doing, and change who does what.

You hold the last word

Approval is a button. Nothing lands, is pushed to GitHub or deployed until you press it. The agents cannot do it for you.

Any language, any stack

The agents read your project and use its own tools. You do not choose a framework or learn a command to start.

GitHub, the familiar way

Pull requests, checks and merging look like GitHub. Pushes only when you say.

OpenMerge pull request

And: a command palette (⌘K), a Studio to edit rules and skills, a Health strip, models per role, and a map of how your code connects.

Take control

Built so nothing surprises you.

The limits are not settings the agents can change. A guard blocks them, and only you can move them.

Nothing deploys automatically
Releases and deploys happen only when you ask for them.
Only the Builder edits code
Everyone else reads and writes documents. Rules, settings and git history are off limits to agents.
Secrets never go in files
Settings hold the name of a variable, never its value. A scan runs before anything is pushed.
Every change waits for your yes
Approve it, send it back, or discard it. Your main branch only changes when you decide.

You can change: the team and who does what, the model for each role, the rules every agent follows, their skills, and the checks that must pass.

Install and use

Three commands to start.

Add it to Claude Code

Install it

Set up your project

You need Claude Code (logged in), Bun 1.2 or newer and git. GitHub CLI is optional, for pull requests. It is open source: the code is on GitHub.

Then, in the dashboard

  1. 1

    Talk. Tell the Product Partner what you want to build.

  2. 2

    Run. Press Run on the top task and watch the team work.

  3. 3

    Decide. Read what changed, then approve, send back or discard.
